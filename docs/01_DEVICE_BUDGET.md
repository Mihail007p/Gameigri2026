# Бюджет производительности: Tecno Pova Neo 3

Это **главный документ проекта**. Любое решение по графике сверяется с этой таблицей.

## 1. Железо (факты)

| Параметр | Значение | Что это значит для нас |
|---|---|---|
| SoC | MediaTek **Helio G85** (MT6769Z), 12 нм | 2×Cortex-A75 @2.0 ГГц + 6×Cortex-A55 @1.8 ГГц. Один поток слабый → логика и draw-call'ы должны быть дешёвыми |
| GPU | **Mali-G52 MC2**, 48 шейдерных блоков, ~96 GFLOPS | Очень мало. Ограничение — **fillrate и количество draw call**, а не полигоны |
| RAM | 4 или 8 ГБ LPDDR4X (реально приложению доступно ~1.5–2.5 ГБ) | Держим память < 350 МБ, текстуры только маленькие |
| Экран | 6.82" IPS, **720×1640**, 90 Гц, 263 ppi | 720p — наш потолок. 90 Гц не нужны: цель 30/40 FPS |
| Накопитель | 128 ГБ eMMC 5.1 + microSD | eMMC медленный → мало файлов, один архив ассетов, без стриминга мелких файлов |
| AnTuTu | ~250 000–324 000 | Уровень «низкий». Для сравнения: средний флагман 2024 — 1 500 000+ |
| ОС | Android 13 (HiOS) | Целевой API level 33+, Vulkan 1.1 / OpenGL ES 3.2 |

**Важно про Mali-G52 MC2:** у него 2 ядра, очень низкая скорость растеризации и болезненная
реакция на **overdraw** (когда один пиксель рисуется несколько раз) и на **смену состояний**
(draw call). Поэтому: минимум прозрачности, минимум мелких объектов, максимум инстансинга.

## 2. Бюджет кадра (цель: 30 FPS = 33.3 мс)

| Статья | Бюджет | Как измеряем |
|---|---|---|
| CPU: логика игры (AI, физика, квесты) | ≤ 5 мс | perf-панель `cpu ms` |
| CPU: подготовка сцены (culling, матрицы) | ≤ 3 мс | perf-панель |
| GPU: рендер | ≤ 20 мс | perf-панель `frame ms` |
| **Draw calls** | **≤ 90** | `renderer.info.render.calls` |
| **Треугольники в кадре** | **≤ 120 000** | `renderer.info.render.triangles` |
| Overdraw | ≤ 2.0× | визуально по прозрачности |
| Память GPU+JS | ≤ 350 МБ | `renderer.info.memory` + DevTools |
| Размер сборки (APK) | ≤ 120 МБ | цель v1.0 |

## 3. Приёмы, которыми мы держим бюджет

1. **Render scale < 1.0.** Рендерим в 0.6–0.75 от 720p и растягиваем.
   На Mali-G52 это самый дешёвый способ поднять FPS: пикселей в 1.8–2.2 раза меньше.
2. **Flat shading + vertex colors.** Нет текстур → нет выборки из памяти, нет mip-map-трафика,
   нет UV. Цвет зашит в вершины. Это и есть наш «стиль».
3. **InstancedMesh** для деревьев/камней/травы: 3000 объектов = 3–4 draw call.
4. **Динамический отсев пропсов**: инстансы пересобираются каждые 0.4 с только в радиусе 70–130 м.
5. **Чанки террейна** 40×40 м, виден радиус 2 чанка (25 штук), переиспользование геометрии из пула.
6. **Слияние статики**: деревня и руины объединяются в 1–2 меша через `mergeGeometries`.
7. **Тени**: одна directional-лампа, карта 1024, тесная ortho-проекция (50 м) вокруг игрока,
   обновляется вместе с игроком. На пресете `low` тени выключены.
8. **Туман** вместо дальней прорисовки: `Fog` скрывает границу подгрузки, дальность 70–110 м.
9. **Нет пост-обработки**: никакой SSAO/bloom/DOF. Тонмаппинг ACES встроен в шейдер рендерера.
10. **Авторагулировка качества** (`core/perf.js`): если медиана кадра > 34 мс — снижаем
    render scale шагом 0.05; если < 24 мс — повышаем. Игрок не видит настроек, игра сама подстраивается.

## 4. Пресеты качества

| Пресет | Render scale | Тени | Радиус пропсов | Чанков | Макс. врагов |
|---|---|---|---|---|---|
| `low` | 0.55 | нет | 70 м | 2 | 4 |
| `medium` (**старт на Pova Neo 3**) | 0.75 | 1024 | 100 м | 2 | 7 |
| `high` | 1.0 | 1536 | 130 м | 3 | 10 |

## 5. Тепловой режим

Helio G85 на 12 нм греется. Через 15–20 минут игры начинается троттлинг (−20…−30% FPS).
Поэтому:
- автоснижение качества **не отключается** никогда;
- цель не 60 FPS, а стабильные 30: меньше нагрузка → меньше нагрев → дольше батарея (7000 мАч = плюс);
- в меню паузы > 20 с рендер останавливается полностью (`paused` → не вызываем `render()`).

- [ ] Обновляется ли это каждый кадр? Если да — сколько объектов?
